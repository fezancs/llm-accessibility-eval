# Deviations from the pre-registered plan

Pre-registration tag: `prereg-v1` (commit: _fill in when tagged_)

Record every change to metrics, prompts, tasks, models, exclusion rules or analysis
made after the tag, BEFORE re-running anything. Each entry is reported in the paper's
threats-to-validity paragraph.

| Date | What changed | Why | Expected effect on results |
|---|---|---|---|
| 2026-11-12 | **Local server: llama.cpp instead of Ollama.** The local models are served by llama.cpp `llama-server` b12004 (Vulkan backend on the open Mesa NVK driver) from the publishers' Q4_K_M GGUF files, pinned by sha256 in `config/models.yaml` (`gguf`). `provider_model_id` is now the server alias. Flags per model: `local/serve_llamacpp.sh`. | On this machine Ollama's release downloaded at < 0.1 MB/s and, without the proprietary NVIDIA driver (no sudo), has no GPU backend; llama.cpp's Vulkan build runs on NVK. llama.cpp also rejects a prompt longer than the context (HTTP 400) where Ollama truncates silently, which the E2 context-exhaustion rule (SPEC 6.1) needs. | Same models, sizes and 4-bit quantisation type as the Ollama tags, but different conversions: results are for these exact files. Latency reflects Vulkan on NVK (slower than CUDA), so local CPDS latencies are hardware-specific. |
| 2026-11-12 | **Sampling defaults set on the server.** Each model's Ollama-library defaults (Qwen3 8B: temperature 0.6, top-k 20, top-p 0.95; Qwen2.5-VL 7B: temperature 0.0001; Gemma 3 4B: 1.0 / 64 / 0.95; Ministral 3 8B: 0.15); unspecified values as Ollama (top-k 40, top-p 0.9, min-p 0), no repeat penalty. The harness still sends none (SPEC 2.1). | llama.cpp's own defaults differ from the provider defaults of the documented setup. | Matches the documented setup's provider defaults. Qwen2.5-VL is near-greedy, so its three E1-Gen samples are close to identical. |
| 2026-11-12 | **Third local E3 family.** Added `local-ministral3-8b` (Ministral 3 8B, family `mistral-local`) as an E3 generator and judge. The `judges:` map now lists the three local judges (cloud map kept in comments). | With two local families, recusal removes every E3c verdict (each pair contains both judges' families), so CMBPE cannot be fitted. LOCAL_SETUP.md asks for a third family. | E3c compares 3 generators (3 pairs per image, all pairs) instead of 8; each pair is judged by the one judge outside both families. |
| 2026-11-12 | **Qwen3 8B output and context.** `max_output_tokens` 8192 -> 32768, served with a 32,768-token context and a q8_0 KV cache. | SPEC 13.1: max_tokens is 64,000 or the model's maximum output if lower; the Qwen3 card recommends 32,768 output tokens (thinking included). 8,192 cut thinking plus long pages (the repair pages are up to ~9.8K tokens). An f16 KV cache does not fit next to the weights on 8 GB. | Fewer truncated E1 outputs. Prompt plus output share the 32K window; a full window ends generation (finish "length"). q8_0 KV quantisation can shift outputs slightly. |
| 2026-11-12 | **Image inputs capped at 1,280 visual tokens** for Qwen2.5-VL 7B and Ministral 3 8B (`--image-max-tokens 1280`); Gemma 3 4B uses its fixed 256 tokens per image. | Uncapped, Ministral's server crashed (bus error) on large images and Qwen2.5-VL needed ~57 s per large image on this GPU. 1,280 is Qwen2.5-VL's documented `max_pixels` example (1280*28*28). | Images above about 1 megapixel are downscaled before encoding (all three judges see similar resolutions). |
| 2026-11-12 | **Harness fixes for a local-only run** (no metric, prompt, task or scoring rule changed): `CONTEXT_RE` also matches llama.cpp's "exceeds the available context size"; `check_keys` needs no key for `local`; the local adapter refuses (never caches) an answer whose model name differs from the requested alias; `e2_padding` keeps the complete turns when a short-context model fills its window before turn 30. | Bugs or gaps found while preparing the run: without them check_keys crashes on local models, context exhaustion goes undetected, a wrong server could answer for another model, and the padding transcript cannot be built on a 32K model. | None on scoring. |
| 2026-11-12 | **E2 padding transcript generated with `local-qwen3-8b`** instead of Claude Haiku 5.5 (no API budget). It stops at the first turn that exceeds the 32K window. | SPEC 6.2 needs a transcript; no paid model is available. | The padding is irrelevant history by design, so its author matters little. A shorter transcript still covers every Lambda the 32K session can reach. |
| 2026-11-12 | **Local run scope** (`budget.yaml` local_profile, run by `local/run_local.sh`): E1 with `local-qwen3-8b` and `local-qwen25vl-7b` (full 120 generations, 48 repairs and 48 audits each); E2 with `local-qwen3-8b`, 1 run (seed 101), pilot first for the SPEC 12 tool-call rule; E3 with the three local vision models on the 120 seeded images and all four procedures. Smoke calls made before the run commit was pushed: check_keys for the four models and E1-Gen G01 sample 0 (both conditions) for Qwen3 8B, with the same code. | Fits one 8 GB GPU in about 1.5 days. | H1 (vendor pairs) and H2 (closed vs. open) cannot be tested; H3 is vacuous (every model is open-weight). E2 statistics rest on one run. No `prereg-v1` tag exists, so the run cannot be described as pre-registered. |
| 2026-10-29 | Added a `local` provider and three self-hosted models (`local-qwen3-8b`, `local-qwen25vl-7b`, `local-gemma3-4b`) that run on an 8 GB consumer GPU via Ollama, at $0. See `docs/LOCAL_SETUP.md`. | No budget for paid API tokens; the only free way to run E2 (whose long contexts exceed every free cloud tier's tokens-per-minute cap) is on local hardware. | A local-only run evaluates small open-weight models instead of the frontier closed models. It cannot test GPT-6, Gemini 4, Claude 5.5 or DeepSeek V4-Pro, so cross-vendor and "best closed vs. open" claims (e.g. H2) are out of scope for that run. Local vision models give weaker alt text, lowering C4/E3 scores. The paper must state that results are for 7–8B open-weight models self-hostable on 8 GB hardware, not the frontier. This is an added capability, not a change to any metric, prompt, task or scoring rule. |
